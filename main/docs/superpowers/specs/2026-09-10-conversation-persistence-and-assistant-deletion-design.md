# 对话恢复与助手删除设计

## 目标

修复重新进入创建页后“只有教学技能、没有历史对话”的状态断裂，并在“我的助手”中补齐可理解、可确认的删除能力。

## 状态设计

- 教学助手、设计对话、未加入的教学技能都按助手 ID 保存在浏览器本地。
- 重新进入已有助手时，同时恢复设计对话和教学技能。
- 新建助手使用新的 ID，因此仍从欢迎语和空设计稿开始。
- 删除助手时同时清理该助手的设计对话与技能选择记录，避免残留数据。

本次只实现本地 Demo 状态，不新增后端接口、回收站或跨设备同步。

## 删除交互

- “我的助手”每行保留原有的主体点击区域，用于继续设计、检测或查看运行记录。
- 行尾增加独立的“删除助手”按钮，不能触发行跳转。
- 点击后显示确认窗口，明确展示助手名称和删除后果。
- 点击“取消”不改变数据；点击“确认删除”后关闭窗口、更新列表数量并保持在“我的助手”。
- 删除最后一个助手后展示空列表状态，仍可通过“创建助手”继续。

## 设计器调整演示

- 教师在右侧展开某项教学技能后点击“让设计器调整”。
- 左侧显示当前正在调整的技能，并提供一条可点击的修改示例；示例只填入输入框，不自动发送。
- 教师发送后，设计器回复修改结果；右侧保持该技能展开并立即呈现修改后的教学步骤。
- 移动端发送修改后自动切回“助手设计稿”，避免修改结果不可见。
- 修改后的对话和技能内容都随助手一起保存，重新进入时保持一致。

## 代码边界

- `useDemoPlatform`：负责对话持久化和原子化删除本地助手数据。
- `MyAssistantsPage`：管理当前待删除助手和确认窗口。
- `AssistantList`：只负责呈现可选的行级删除入口，不持有删除状态。
- `DesignerPage` 和 `DesignerChat`：管理调整上下文、示例填入及移动端结果切换。
- `App`：连接页面事件与状态层，不包含确认交互细节。

## 验证

- 创建三项教学技能后刷新页面，历史对话和技能同时存在。
- 新建另一个助手时，对话区只有欢迎语，设计稿为空。
- 取消删除后助手仍存在。
- 确认删除后列表、数量和本地关联状态同步更新。
- 删除按钮不会打开助手详情。
- 点击调整示例并发送后，右侧对应技能显示新增步骤；刷新后修改仍存在。
- 桌面端和移动端均可操作，并保持无横向溢出。

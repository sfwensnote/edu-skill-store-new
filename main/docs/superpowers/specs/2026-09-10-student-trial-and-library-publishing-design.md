# 学生试用与助手库发布设计

## 目标

把检测后的产品阶段明确为“小范围投放给学生试用”，由学生使用记录形成试用报告，再由教师决定是否公开发布到助手库。

## 流程

`完成检测 → 投放试用 → 查看学生试用记录 → 查看试用报告 → 发布到助手库`

- 完成全部检测情境后，主按钮显示“投放试用”。
- 投放后进入“试用”页面，不要求教师发起或完成对话。
- 试用页面复用现有学生端入口和运行记录，展示学生对话次数、教学技能触发和异常情况。
- 教师可随时查看试用报告；Demo 不额外设置试用人数、时长或最低对话量门槛。
- 报告页在试用阶段显示“发布到助手库”。
- 发布后助手状态从“试用中”变为“运行中”，`isPublic` 设为 `true`，助手进入公开助手库并打开公开详情页。

## 页面语义

### 检测完成页

- 主标题仍为“检测完成”，说明检测结论。
- 主操作由“确认投入使用”改为“投放试用”。
- 次操作保持为“返回调整”。

### 试用页

- 页面状态显示“试用中”。
- 页面说明明确为“小范围投放给学生，以下为学生试用记录”。
- 保留“打开学生端”和“查看试用报告”两个操作。
- 运行数据沿用 Demo 记录，并明确代表学生试用情况。

### 试用报告页

- 标题为“试用报告”，汇总学生使用概况、教学技能触发和主要异常。
- 页面底部或报告结论区提供主按钮“发布到助手库”。
- 发布动作不增加审核、版本市场、付费或权限配置。

### 发布后

- 公开助手排在助手库列表前部，并参与现有搜索和筛选。
- 助手库默认总数在演示基数上加上教师公开助手数量。
- 公开详情页继续使用现有介绍、教学技能和“开始使用”结构。
- “我的助手”仍保留该助手，状态显示“运行中”。

## 状态与代码边界

- 增加 `TRIAL` 状态：`TESTED` 表示检测完成但尚未投放，`TRIAL` 表示学生试用中，`ACTIVE` 表示已发布运行。
- `TestingPage` 只负责完成检测并触发投放试用。
- `LogsPage` 根据状态显示“试用中”或“运行中”的页面语义。
- `ReportPage` 根据状态显示试用报告及发布入口，或发布后的运行报告。
- `useDemoPlatform` 负责将发布动作原子化为 `status: ACTIVE` 与 `isPublic: true`。
- `LibraryPage` 接收静态助手和教师已公开助手的合并列表；不直接读取工作台状态。

## 验证

- 完成七项检测后点击“投放试用”，进入显示“试用中”的记录页。
- 试用过程不要求教师完成对话。
- 试用报告显示“发布到助手库”。
- 发布后助手出现在助手库列表和搜索结果中，打开的是公开详情页。
- 发布后“我的助手”状态为“运行中”，报告页不再重复显示发布按钮。
- 未发布草稿和试用中助手不会出现在公开助手库。

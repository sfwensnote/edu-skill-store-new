# 创建助手：教学方法由教师确认

本次仅替换创建流程。助手库、我的助手、运行日志保持现有布局。

## 设计逻辑

采用既有界面延伸模式，参照「创建助手.png」「教学表格.png」。白底、浅灰蓝边框、现有蓝色主按钮与系统字体；8px 圆角，间距以 8px 为基础。第一屏居中聚焦输入；第二屏左侧约 35% 展示原始想法，右侧约 65% 为主表单；窄屏上下排列。视觉变化 2、动效 1、信息密度 6、素材依赖 1、既有风格保真 10。不添加装饰动效或全局侧栏。

## 教育逻辑与数据流

新建助手默认预填初中数学「一元一次方程练习」示例，包括原始想法、问题、目标、两组情况与做法及教学原则。所有字段可修改，已有本地草稿优先恢复，不用默认值覆盖。默认值不代表技能已生成，仍须依次确认。

1. 原始想法只记录 originalIdea / grade / subject / teachingScene，不调用生成器，不生成技能。
2. 教师补充问题、目标、条件与做法、可选原则。提供明确的「使用数学教学示例」入口；示例中的两种情况均已写在原始想法里，再整理为待确认方法。非示例内容不杜撰策略，已有方法不被预填覆盖。
3. 点击「形成 Skill」即确认详细方法。纯函数原样封装：problem + expectedOutcome → purpose，首条 condition → trigger，teachingSteps → steps，principles → constraints。
4. 技能预览可展开、返回修改、选择是否加入。至少选择一项才能开始检测。
5. 检测沿用现有界面，逐条展示本次教师的方法并确认，不再套用固定数学题。当前仅演示方法核对，不能证明真实模型能力。核对完成后显示助手创建成功，提供进入我的助手及原有投放试用入口。

## 技术实现

- `shared/teaching-method.ts` 定义表单结构与无模型调用的封装函数。
- 新技能持有 description 和结构化 steps；summary / behaviorSteps 是为旧版页面保留的派生兼容字段，不是另一套教学策略。
- 创建草稿按助手 id 保存在 localStorage；修改原始想法不会覆盖教学方法。删除助手时同时清除创建草稿。
- 创建过程中同步草稿名称、目标和场景，提供「保存并退出」和当前阶段标识。重新进入恢复原阶段；检测的逐项进度也按当前技能内容保存，修改技能后不复用不匹配的结果。
- 修改已有技能时从该技能恢复方法，只替换选中的技能，不清空其他技能。旧技能没有记录的后续介入条件留空，由教师补充。
- 修改已确认内容会退回草稿、取消公开状态，要求再次封装与检测。
- 无新增依赖。复用现有 Button 与技能预览组件，表单采用原生标签、必填校验和键盘操作。
- 测试覆盖空方法拒绝、原文映射、不新增策略、可选原则及检测内容来源。

## 范围

本次未接入真实设计或教学模型，未改后端流程；新技能核对结果不代表模型检测通过。旧 Demo 的示例页面和历史助手保留兼容。

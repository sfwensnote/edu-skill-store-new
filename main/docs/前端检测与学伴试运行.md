# 当前前端检测与学伴试运行

2026-10-12。按用户最新范围暂停后端，GitHub Pages 固定使用 `VITE_SERVICE_MODE=preview` 且不配置 API 地址。页面沿用原设计；界面不增加 Demo／演示标识，但状态使用“教师已核对”，不宣称真实模型检测已通过。

## 可操作流程

1. 创建完整 SKILL，最后填写结束条件；进入检测，每次只显示一个情况。确认当前情况后进入下一个，最后核对结束引导。
2. 回复从该方法现有有限预览规则生成，第二种情况固定匹配第二步，不随对话轮数推进；四项结果提示教师核对，不自动给出通过分数。
3. 可返回前一个情况；刷新恢复浏览位置和确认进度。创建项可现场修改情况描述、教师做法或结束条件，保存同步原 SKILL 并更新回复；当前及后续情况重新确认，结束条件修改后从头确认。集市添加项仍只读。全部确认后可以发布到集市，或挂载到学伴。
4. 学伴详情点击“开始试运行”进入独立地址 `#/companions/:id/practice`。页面以对话为主，不再提供可编辑的场景表单；学生身份输入支持 Enter 发送、Shift+Enter 换行，中文输入法组合中的 Enter 只提交候选、不发送。首次进入预填预置的学生开场表达，并提供“填入学生表达”。
5. 刷新恢复同一段对话；结束后输入区只读并保留记录，“新对话”另开一段，“历史记录”可切回旧对话。场景、挂载方法和材料均来自本次快照，修改原学伴只影响新对话。

该模式没有真实自然语言语义判断。SKILL 检测逐项展示教师方法；学伴试运行根据预输入和有限表达规则匹配方法，不按对话轮次自动推进，无法匹配时围绕本次任务追问，不编造触发记录。演示记录不能作为真实 Agent 执行证据。结束案例是收束方式展示，仍由教师核对；材料不会假装经过真实模型理解。

学伴教学要求和侧栏方法说明改为结构化字段：学习场景、开始条件、情况／教师做法、教学原则、结束条件。保留教师原文，不把已带句号的情况再接冒号和做法；文字上下间距由组件控制，避免双换行造成大片空白。

## 数据和模块

- `shared/execution-preview.ts`：共用教师方法的情境和回复，不产生真实模型通过结论。
- `case-review.ts`／`MethodReviewPage.tsx`：逐情况进度、就地修改与原方法保存；核对和原方法保存失败时回滚，不假报成功。
- `shared/companion-practice.ts`：整场学伴演示的预输入和有限表达匹配，独立于 SKILL 单项核对。
- `src/features/execution/preview-runtime.ts`：适配现有检测／试用合同，读写浏览器、核对资格、快照及幂等记录。
- `shared/companion-cases.ts`：内置完整案例（分数错因辅导）与配套方法；`applyCompanionCase` 把整套内容填入学伴草稿，`withCompanionCaseSkills` 只为该学伴补入案例方法。案例不是教师核对结果，不写入我的 SKILL 或集市。
- `CompanionPracticePage.tsx`：独立试运行页与聊天区；预览模式复用浏览器运行时，服务端模式复用原受控试用面板。
- `CompanionPracticePanel.tsx`：旧的内嵌试运行面板，目前只在服务端模式由学伴详情复用。
- `api.ts`：显式 server 模式继续使用原真实接口；后台失败不退回样例。preview 模式完全不请求 `/api/`。

记录在 `teaching-method.execution-preview.v1:<accountId>`，按浏览器账号隔离；原 SKILL、集市、学伴、账号键和固定清理标记不变。重新核对或内容修改不沿用旧资格；试运行固定当次方法与场景，源资料更新后开始新一轮。存储失败不确认、不追加回复、不跳转；原记录保留，可重试。损坏记录报错而不覆写。

前端登录与保存仍限同一浏览器，不是云端账号。学生链接不开放；不伪造跨设备学生会话或回收报告。未来接 FastAPI 时，浏览器核对不能导入为真实验证资格，需完成真实检测。未来方案见 [FastAPI 后端](FastAPI后端架构与接口设计.md)。

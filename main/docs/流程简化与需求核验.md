# 流程简化与需求核验

更新日期：2026 年 10 月 9 日。验收依据是当前有效的聊天要求：本地客户演示、功能可交互、简明实用、名称统一、返回连贯，并保留已认可的视觉样式。

## 这轮实际简化了什么

| 原先的负担 | 当前行为 |
| --- | --- |
| 创建入口先经过说明页 | 首页或顶部创建直接进入填写想法 |
| 梳理后进入独立预览页，再确认 SKILL | 形成 SKILL 后直接进入方法核对；需要预览时打开页内弹窗 |
| 核对结束经过试用列表、预览和摘要中转 | 核对 → 学生视角预览 → 完成返回作品；核对记录同页折叠 |
| 方法详情同时堆叠应用、复制、收藏等操作 | 主要显示核对／预览和编辑；次要操作放入更多菜单 |
| 我的作品有两套叠加搜索条件 | 顶部一个搜索框；不再叠加旧的隐藏分类搜索 |
| 新建教学任务混合“学习活动”和方法应用 | 教学任务只布置探究作品；方法应用配置放在我的作品 |
| 空白新建页也要求保存或放弃 | 仅选择资源或实际修改后保护未保存输入 |
| 不可用的发布、启用和助手目标占据流程 | 当前主要操作为保存与预览；未开放助手挂载收在折叠说明中 |

目前常用路径：

- 教学方法：填写想法 → 梳理方法 → 核对 → 学生视角预览 → 我的作品。六个问题在梳理页逐题回答，不是六个独立页面。
- 探究作品：选择成果 → 编辑确认 → 保存；情境题、任务链和 PBL 独立，不强制逐级升级。
- 教学任务：我的任务 → 新建教学任务 → 选择作品、任务要求、可选支持、预览保存。
- 方法应用：我的作品 → 应用 SKILL → 选择已有任务、模拟检查、保存配置；不生成学生任务。

| 学生视角的方法步骤看得懂、能直接预览 | 公共 MethodSteps 配对显示学生表现与教师做法；每步可预览；手机不挤压、不横向溢出 |
| 核对、预览、分享与返回连贯 | 形成后直接核对；预览后回作品或分享；多方法只分享当前方法；不存在的方法不冒用另一项 |
| 创建 SKILL 不莫名增加教学任务 | 创建、核对、预览不写入任务；历史方法试用归入我的作品；teaching-tags 与 method-review 验证任务数量不增加 |
| 去掉教学助手库跳转，简化空间术语 | 公共导航只有首页、集市、我的作品、教学任务；助手库旧地址只为兼容保留，没有常用跳转 |
| 选择教学作品搜索框可用 | 修复全站样式冲突造成的双边框和类型文字换行；测试名称／知识点、类型组合、无结果及 1440／1120／768／390px |
| 保存、刷新、离开和旧数据安全 | 草稿有 ID；保存失败保留输入；已提交快照不覆盖；方法配置和任务分开；functional-audit、teaching-activity 与 workshop 检查 |

“分类至少一项最多两项、额外标签最多三项”随后被明确取消，因此没有重新引入该限制。按后续指令，当前教学分类必选一个，自定义标签沿用现有最多五个、每个二十字的限制。

## 设计与审查决定

采用保留现有体系的改版：面向教师的桌面工作台，兼顾平板和手机。保留深绿主色、白色卡片、浅灰绿背景、中文系统字体、公共导航和已有 SVG；降低信息密度，没有新增插画依赖或装饰动画。

主要视觉重点是当前教师问题、教师方法和下一步。说明保留在需要做决定的位置；来源、核对记录、历史试用和进阶配置使用折叠区域。重复的卡片边框、步骤编号和搜索框不再叠加。

旧草稿、方法、作品、助手、报告和步骤地址继续兼容。简化界面不清空本机存储，也不把旧记录当作真实学生运行。

## 三轮改动与修正记录

1. 第一轮减少创建确认页和摘要中转。实际走查发现新方法仍被旧状态规则留在草稿，以及空任务离开时错误弹出未保存提示；已修复状态保存和修改判断。
2. 第二轮检查任务／方法分离、搜索、标签与保存。修复作品搜索的全局 CSS 冲突，方法详情明确主要操作，补上第二步预览与当前方法分享，防止多方法一起被误分享。
3. 第三轮做交互与截图回归。修复应用配置查看详情时的导航高亮，并清除旧详情样式给新方法步骤添加的重复编号及手机缩进；未采用方法重新加入核对时，保存失败不会冒充成功。

每次发现问题后先定位原因，再修正对应实现和回归条件。旧测试中要求独立确认页、双路径入口或未核对即可分享的断言，已按当前产品规则更新，没有通过放宽保存、版本或真实性校验来让检查通过。

## 检查结果

- 41 项相关单元检查通过，覆盖方法结构、分类与标签、作品可用性、应用相容性、版本、保存快照、目录与路由。
- 最终 43 项浏览器交互场景通过，覆盖首页、方法创建、就地修改、集市、作品、任务、应用配置、学生预览、持久化失败和旧地址返回。
- TypeScript 与 Vite 构建通过。保留依赖库注释和单包体积的既有构建提示。
- 桌面、平板与 390px 窄屏检查无横向溢出；任务操作栏可见，方法步骤可直接预览。
- 相关流程的错误监听未捕获新的页面运行错误；前端主要流程不请求模型 API。
- 仅使用隔离测试资料操作写入与存储失败；没有清空用户浏览器数据。

## 实现边界

按已确认的前端演示范围，当前有固定问题、固定引导、规则模拟、本机草稿与预览记录。未接入真实模型、学生发布、学生账号、正式 SKILL 执行及跨设备同步。界面保留简短事实说明，不展示虚构通过率，也不让保存或分享冒充发布启用。

“去 AI 味”和“足够简明”包含主观感受，不能靠测试声明百分之百满足；本轮以减少必经页面、重复输入、重复确认和含混术语作为具体验收依据。

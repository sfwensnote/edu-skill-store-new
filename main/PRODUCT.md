## 用户与目标

面向在职教师，将课堂中的判断、做法与原则整理为可复用的教学 SKILL。PBL、情境设计和教学活动逐步退出产品。

## 当前功能合同

2026-10-11 界面与图标调整：我的 SKILL 顶部统计卡移除，保留全部／我创建的／从集市添加侧边分类，手机仍使用分类选择框。各页沿用原设计，统一标题、内容宽度、顶部区域和首页背景。我的学伴按参考图展示真实头像、学习场景、挂载 SKILL 和材料，提供搜索、筛选、排序、查看、编辑、复制草稿及确认删除，不添加样例或上传材料按钮；详情按场景、SKILL、材料分区。SKILL 图标由教学分类确定，教师可改颜色或上传自定义图片，创建、编辑、发布及集市添加同步保留图标。未配置图标的旧方法使用分类图案。见 [界面统一与图标验收](docs/界面统一与图标验收.md)。

2026-10-11 学伴与试用调整：我的学伴独立使用四步创建，顺序为基本信息、选择 SKILL、教学场景、预览与保存，保留步骤侧栏，前三步不显示学伴预览；最后一步完成填写后，预览独立排在确认与保存区域上方。表单标题去掉数字序号与点，顶部改用绿色机器人插画，预设形象为戴眼镜的教师、女教师与机器人，自定义上传以绿芽图案表示。教学场景只有学习对象、学习情境两个选择框，学习任务与目标一个多行文本框；教学材料与活动设计选填并折叠。学伴可选形象或上传头像，预览只呈现填写的信息。用户最新要求清除旧任务，工作区启动时清空旧教学任务、活动草稿与学伴九项旧要素和活动设计，旧学伴回到草稿；保留 SKILL、学伴名称、挂载及材料，新三项场景继续保存。清理写入失败不启动工作区，可重试。保存失败保护未存输入。挂载按钮打开所选学伴详情，草稿也能查看，不复制方法。我的 SKILL 及其详情不提供试用；新 SKILL 发布到集市后自动根据当前方法生成案例，使用现有有限回复规则展示挂载效果。仍先检验再发布，不自动公开草稿。

本次导航审查修复同一 SKILL 详情与弹窗 key 冲突导致旧页面残留、顶栏跳转失效的问题。所有相关组件标识带类型前缀，路由变化关闭挂载与发布弹窗；失效方法链接跟随来源返回。具体检查见 [学伴创建与导航审查](docs/学伴创建与导航审查.md)。

2026-10-11 局部调整：登录／注册成功后首先展示首页，已登录时刷新保留当前页面。方法检验页顶部提供“返回上一步”，桌面与手机进入即可看到；可返回前一项查看，确认进度保留，第一项进入方法编辑，完成页返回最后一项。浏览位置与确认数量分开保存，方法修改后的原失效规则保留。先前的教学任务要素表由上述三项教学场景替代。

检测与作者学生视角预览保留原有限回复逻辑，检测页分别呈现学生输入、模型回复、预期做法和原则，由教师确认。这些功能不进行任意问题的语义判断，教师确认不等于模型执行通过或教学效果已验证。按用户最新要求，集市、检测和作者预览采用正式产品的呈现，界面不再显示 Demo、演示、预置等标识；参考内容使用“案例”“参考回答”。旧来源说明在显示时隐藏，来源快照不改写。待核对、教师已确认、保存失败等操作状态如实保留。

按用户补充要求，移除 PBL、项目式学习、情境任务指导、任务链等分类和标签；创建、集市、我的 SKILL 统一使用同一套展示规则。旧板块筛选与相应缓存取消；已有资料和来源快照完整保留，旧分类展示为未分类，编辑时需重新选择。普通知识点标签保留。

旧情境、任务和应用配置的直接路由与已有资料暂留兼容，底层模块待后续批次清理；以下关系仅描述这些保留代码。

SKILL 的当前挂载入口进入学伴选择；旧任务应用编辑器已经删除。旧任务内容已按用户授权清空，其失效直接地址提供返回入口。

任务要求不修改源作品，方法应用不改写教学决策。已有学习记录的任务保留快照，后续调整另建副本。创建、核对或预览 SKILL 都不增加教学任务。

## 产品原则

- 先表达经验，再整理方法；不从一句想法编造教师的全部步骤。
- 教师最终修订优先于问答记录；未提交输入只存为草稿。
- SKILL 创建仅“我的原则”选填，其余全部必填：教学想法、学段、学科、教学分类、至少一个标签、SKILL 名称与简介、想解决的问题、希望学生达到、什么时候开始、每种情况与做法、结束条件。缺项不能形成 SKILL，仍可保存和恢复草稿；原则问答可以跳过，名称与简介由教师填写。
- 内容核对、规则模拟、真实执行与教学效果分别记录，不相互替代。
- 收藏、分享、配置和启用分别处理，本机展示不改变运行状态。
- 持久化成功才显示操作成功；失败保留内容并提供重试。
- 每一步突出当前问题或任务，次要操作收进菜单和折叠内容。
- 界面使用简体中文与大写 SKILL，统一使用“教学分类”，与集市四个分类对应（课堂提问、错因辅导、智能练习、知识讲解）；教师可以额外填写知识点等标签。
- 保留绿色、白色与浅灰绿色设计体系，减少宣传文案、重复边框、同一页面上的重复搜索和不能完成的操作。

## 实现边界

2026 年 10 月 10 日，用户明确登录系统先做 Demo，真实登录和云端存储留到后续。当前新增教师、管理员两种账号的浏览器内登录、教师注册和管理员停用／启用。首个教师账号保留上一版清理后新建的资料，其他教师拥有独立的 SKILL、添加项、草稿与核对记录；退出、重新登录和刷新不删除已保存内容。同一浏览器内可切换账号展示发布与只读添加；不同设备、不同浏览器或无痕窗口之间不共享账号和作品。停用会使已登录的教师退出，保留资料，启用后需重新登录。

此登录演示不调用原 Express 认证接口，没有服务端权限校验；浏览器内角色不能保护真实教师资料。密码在浏览器中按盐值计算摘要保存，但不把客户端摘要及角色展示称作生产认证。后续需接入真实账号服务、数据归属验证与云数据库。现有一次性 SKILL 清理标记保持原值，不因加入登录重新清空内容。

当前前端不调用真实 LLM，数据保存在同一浏览器的 localStorage。追问为预设七问，自定义探究内容提供教师编辑框架，不声称自动完成任意学科生成、答案校验或语义适配。原 Express 服务增加可单独检查的 SKILL 预览接口，沿用已有模型适配；只用本机协议夹具验证，Pages 页面不调用此接口、不部署后端。

学生入口是教师的学生视角预览，提交只保存在本机。真实学生发布、学生账户、教学助手运行、SKILL 正式启用、执行轨迹、学习效果验证与跨设备同步尚未接入，相关正式入口不可操作。

原有 Express、SQLite、认证、模型与材料解析模块保留，当前页面主要流程没有调用这些服务。本地服务只监听 `127.0.0.1`；经用户授权，演示前端可通过 GitHub Actions 部署到 GitHub Pages。Pages 只托管静态构建，作品仍保存在访问者浏览器，不运行上述后台模块。
